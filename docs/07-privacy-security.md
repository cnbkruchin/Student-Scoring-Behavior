# 07 PDPA และความปลอดภัย

> ระบบนี้เก็บ **ข้อมูลส่วนบุคคลของผู้เยาว์เกี่ยวกับพฤติกรรมและการลงโทษ**
> ซึ่งเป็นข้อมูลที่อ่อนไหวและสร้างความเสียหายได้สูงหากรั่วไหล
> ส่วนนี้จึงไม่ใช่ส่วนเสริม แต่เป็นข้อกำหนดขั้นต่ำที่ต้องทำให้ครบก่อนเปิดใช้จริง

## 7.1 ฐานทางกฎหมายที่เกี่ยวข้อง

| กฎหมาย/ระเบียบ | สาระที่กระทบระบบ |
|----------------|------------------|
| พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) | การเก็บ ใช้ เปิดเผยข้อมูลนักเรียน ต้องมีฐานทางกฎหมาย และผู้เยาว์ต้องได้รับความยินยอมจากผู้ปกครอง |
| ระเบียบ ศธ. ว่าด้วยการลงโทษนักเรียนและนักศึกษา พ.ศ. 2548 | ลงโทษได้ 4 สถานเท่านั้น ห้ามลงโทษด้วยวิธีรุนแรงหรือแบบกลั่นแกล้ง |
| พ.ร.บ.คุ้มครองเด็ก พ.ศ. 2546 | ห้ามเปิดเผยข้อมูลที่อาจก่อความเสียหายแก่เด็ก (มาตรา 27) |
| พ.ร.บ.การรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562 | หน่วยงานรัฐต้องมีมาตรการป้องกันและแผนรับมือเหตุ |

**ฐานทางกฎหมายที่ระบบนี้ใช้**

| กิจกรรม | ฐานทางกฎหมาย |
|---------|--------------|
| เก็บข้อมูลนักเรียนและบันทึกพฤติกรรม | ภารกิจของรัฐ / หน้าที่ตามกฎหมายของสถานศึกษา (ไม่ต้องขอความยินยอม) |
| **เผยแพร่ชื่อ-ภาพบนหน้าเว็บสาธารณะ** | **ความยินยอม** (ต้องขอจากผู้ปกครองแยกต่างหาก) |
| ส่งข้อมูลให้ผู้ปกครองผ่าน LINE | ภารกิจของรัฐ แต่ต้องแจ้งวิธีการในประกาศความเป็นส่วนตัว |

> ประเด็นที่โรงเรียนมักพลาด: คิดว่า "แบบมอบตัวมีข้อความยินยอมทั่วไปแล้ว" ครอบคลุมทุกอย่าง
> ความจริงคือการเผยแพร่ต่อสาธารณะต้องขอความยินยอมแบบ **เฉพาะเจาะจง แยกรายการ และถอนได้**
> แนะนำให้แนบแบบยินยอมแยกใบพร้อมเอกสารมอบตัว โดยมีช่องให้เลือกทีละข้อ (ชื่อเต็ม / ภาพถ่าย)

## 7.2 มาตรการที่ต้องมี

### การจัดการข้อมูล
- เก็บเท่าที่จำเป็น — ไม่เก็บเลขบัตรประชาชนถ้าไม่ได้ใช้จริง ถ้าเก็บต้องเข้ารหัส (`students.citizen_id_enc`)
- แยกฐานข้อมูลจริงกับฐานทดสอบ ห้ามใช้ข้อมูลนักเรียนจริงในระบบทดสอบ (ใช้ `db/seed_demo.sql`)
- กำหนดอายุการเก็บ — ค่าตั้งต้น 5 ปีหลังพ้นสภาพ (`retention.years_after_leave`)
  จากนั้นทำให้ไม่ระบุตัวตน (anonymize) แต่คงสถิติรวมไว้เพื่องานประกันคุณภาพ

### การเข้าถึง
- บังคับใช้เมทริกซ์สิทธิ์ใน `docs/05-workflows.md` ที่ระดับ API ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ
- บัญชีผู้บริหารและผู้ดูแลระบบต้องเปิดการยืนยันตัวตนสองชั้น (2FA)
- ทบทวนสิทธิ์ทุกต้นปีการศึกษา — ครูที่ย้ายออกต้องปิดบัญชีทันทีในวันที่มีผล
- ห้ามใช้บัญชีร่วมกัน (เช่น บัญชี "ครูเวร" ที่ทุกคนรู้รหัส) เพราะ audit log จะไร้ความหมาย

### การบันทึกร่องรอย
บันทึกลง `audit_logs` ทุกกรณี: เข้าสู่ระบบ (สำเร็จ/ล้มเหลว), สร้าง/แก้/ลบบันทึก,
อนุมัติ/ปฏิเสธ, เปิดดูข้อมูลรายบุคคลของนักเรียนที่ไม่ได้อยู่ในความรับผิดชอบ,
ส่งออกรายงาน, แก้ไขค่าตั้งค่าและหลักเกณฑ์

### ความปลอดภัยเชิงเทคนิค
| มาตรการ | รายละเอียด |
|---------|-----------|
| HTTPS | บังคับทั้งระบบ พร้อม HSTS |
| รหัสผ่าน | แฮชด้วย bcrypt/argon2 บังคับเปลี่ยนรหัสตั้งต้นเมื่อเข้าใช้ครั้งแรก |
| ไฟล์หลักฐาน | เก็บนอก document root เข้าถึงผ่าน signed URL ที่มีอายุจำกัด ไม่ใช่ลิงก์ตรง |
| สำรองข้อมูล | อัตโนมัติทุกวัน เก็บนอกสถานที่ **และทดสอบกู้คืนอย่างน้อยปีละ 1 ครั้ง** |
| ป้องกันการยิงรหัส | จำกัดจำนวนครั้งการเข้าสู่ระบบ + CAPTCHA |
| อัปเดต | ติดตามช่องโหว่ของ framework และอัปเดตอย่างสม่ำเสมอ |

> ข้อ "ทดสอบกู้คืน" สำคัญมาก การสำรองข้อมูลที่ไม่เคยทดสอบกู้คืน เท่ากับไม่มีการสำรองข้อมูล

## 7.3 สิ่งที่ห้ามทำเด็ดขาด

1. ❌ แสดงรายชื่อ/คะแนนของนักเรียนที่ถูกหักคะแนนบนหน้าเว็บสาธารณะหรือบอร์ดหน้าโรงเรียน
2. ❌ ประกาศคะแนนความประพฤติหน้าเสาธงหรือในกลุ่มไลน์ห้องเรียน
3. ❌ ส่งออกข้อมูลนักเรียนทั้งหมดเป็น Excel เก็บไว้ในเครื่องส่วนตัวหรือแฟลชไดรฟ์
4. ❌ ใช้ข้อมูลคะแนนความประพฤติเป็นเกณฑ์ตัดสิทธิ์ทางการศึกษาโดยไม่มีระเบียบรองรับ
   (เช่น ห้ามเข้าสอบ ห้ามรับใบ ปพ.) — กระทบสิทธิขั้นพื้นฐานทางการศึกษา
5. ❌ ให้บุคคลภายนอก (เช่น ผู้พัฒนาระบบ) เข้าถึงฐานข้อมูลจริงโดยไม่มีข้อตกลงประมวลผลข้อมูล
6. ❌ เก็บภาพถ่ายหลักฐานที่มีเนื้อหาละเมิดศักดิ์ศรีนักเรียน

## 7.4 เอกสารที่โรงเรียนต้องจัดทำก่อนเปิดใช้

- [ ] ประกาศความเป็นส่วนตัว (Privacy Notice) สำหรับนักเรียนและผู้ปกครอง
- [ ] แบบหนังสือให้ความยินยอมเผยแพร่ชื่อ-ภาพบนสื่อของโรงเรียน (แยกรายการ ถอนได้)
- [ ] ระเบียบโรงเรียนว่าด้วยคะแนนความประพฤติ ผ่านความเห็นชอบของคณะกรรมการสถานศึกษา
- [ ] คำสั่งแต่งตั้งคณะกรรมการกิจการนักเรียนและคณะกรรมการพิจารณาอุทธรณ์
- [ ] บันทึกรายการกิจกรรมการประมวลผลข้อมูล (RoPA) ตาม PDPA มาตรา 39
- [ ] ข้อตกลงการประมวลผลข้อมูล (DPA) กับผู้พัฒนา/ผู้ให้บริการโฮสต์
- [ ] แผนเผชิญเหตุกรณีข้อมูลรั่วไหล (ต้องแจ้ง สคส. ภายใน 72 ชั่วโมง)
