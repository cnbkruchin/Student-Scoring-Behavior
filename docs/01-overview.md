# 01 ภาพรวมระบบ

## 1.1 วัตถุประสงค์

| ข้อ | วัตถุประสงค์ |
|-----|-------------|
| 1 | จัดเก็บข้อมูลความประพฤตินักเรียนอย่างเป็นระบบ ตรวจสอบย้อนหลังได้ แทนการใช้สมุดบันทึกกระดาษ |
| 2 | ใช้ระบบคะแนนที่โปร่งใส นักเรียนและผู้ปกครองรู้สถานะตนเองได้ตลอดเวลา |
| 3 | **ส่งเสริมความดีมากกว่าลงโทษ** ด้วยกระดานเกียรติยศบนหน้าหลัก |
| 4 | ให้ครูที่ปรึกษาและฝ่ายกิจการนักเรียนเห็นนักเรียนกลุ่มเสี่ยงได้เร็ว ก่อนเกิดปัญหารุนแรง |
| 5 | ออกรายงานที่ใช้ได้จริงกับงานประกันคุณภาพ SAR ปพ. และรายงาน สพม. |

## 1.2 ผู้ใช้งานและสิทธิ์

| บทบาท | สิทธิ์หลัก |
|--------|-----------|
| ผู้ดูแลระบบ | จัดการผู้ใช้ ปีการศึกษา ห้องเรียน หลักเกณฑ์ ค่าตั้งค่าทั้งหมด |
| ฝ่ายกิจการนักเรียน | อนุมัติ/ปฏิเสธบันทึก ออกคำสั่งลงโทษ พิจารณาอุทธรณ์ ออกรายงานทุกประเภท |
| หัวหน้าระดับชั้น | อนุมัติบันทึกในระดับชั้นที่รับผิดชอบ ดูรายงานระดับชั้น |
| ครูที่ปรึกษา | ดูข้อมูลนักเรียนในห้องที่ปรึกษาทั้งหมด บันทึกพฤติกรรม ติดต่อผู้ปกครอง |
| ครูผู้สอน | บันทึกพฤติกรรมนักเรียนทุกคน (รอการอนุมัติ) ดูได้เฉพาะบันทึกของตนเอง |
| ผู้บริหาร | ดูแดชบอร์ดและรายงานภาพรวม (อ่านอย่างเดียว) |
| นักเรียน | ดูคะแนนและประวัติของตนเอง ยื่นอุทธรณ์ ดูกระดานเกียรติยศ |
| ผู้ปกครอง | ดูคะแนนและประวัติของบุตรหลาน รับการแจ้งเตือน รับทราบคำสั่งลงโทษ |
| สาธารณะ | ดูเฉพาะกระดานเกียรติยศบนหน้าหลัก (ไม่เห็นข้อมูลการหักคะแนนใด ๆ) |

> **หลักการสำคัญ** สิทธิ์ "ครูผู้สอนทุกคนบันทึกได้ แต่ต้องผ่านการอนุมัติ" ทำให้เก็บข้อมูลได้ครอบคลุม
> โดยยังคุมคุณภาพและความเป็นธรรมไว้ได้ ไม่ให้ครูคนเดียวตัดคะแนนนักเรียนได้ตามอำเภอใจ

## 1.4 เทคโนโลยีที่แนะนำ

| ชั้น | ข้อเสนอ | เหตุผล |
|------|---------|--------|
| ฐานข้อมูล | **PostgreSQL 14+** | รองรับ jsonb, window function, partial index, trigger ครบ และฟรี |
| หลังบ้าน | Laravel (PHP) หรือ NestJS/FastAPI | Laravel เหมาะถ้าโรงเรียนมีโฮสต์เดิมและบุคลากรคุ้น PHP |
| หน้าบ้าน | Next.js หรือ Blade + Alpine.js | หน้าสาธารณะควรเป็น static/SSR เพื่อรับโหลดวันประกาศผลได้ |
| มือถือครู | PWA (ติดตั้งบนหน้าจอได้ ใช้กล้องสแกน QR) | ถูกกว่าและดูแลง่ายกว่าแอปเนทีฟ |
| แจ้งเตือน | LINE Messaging API | ผู้ปกครองไทยใช้ LINE เป็นหลัก อัตราการเปิดอ่านสูงกว่า SMS |
| รายงาน | wkhtmltopdf / Puppeteer + PhpSpreadsheet | ออกเอกสารราชการฟอนต์ไทย (Sarabun) ได้ถูกต้อง |

## 1.5 ขอบเขตที่ระบบนี้ "ไม่" ทำ

เพื่อไม่ให้โครงการบานปลาย ระยะแรกยังไม่รวม

- การเช็กชื่อเข้าเรียนรายคาบ (ควรเชื่อมกับระบบเช็กชื่อเดิมหรือ SGS แทน)
- การวัดผลการเรียน/เกรด (เป็นหน้าที่ของ SGS/Bookmark)
- ระบบคัดกรอง SDQ/EQ เต็มรูปแบบ (แต่เตรียมช่องเชื่อมต่อไว้ ดู `docs/08-roadmap.md`)
