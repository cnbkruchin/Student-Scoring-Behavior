# 08 ข้อเสนอแนะและแผนพัฒนา

## 8.1 ประเด็นที่โรงเรียนต้องตัดสินใจก่อนเริ่มพัฒนา

โครงสร้างในรีโปนี้รองรับได้ทุกทางเลือก แต่ต้องเลือกให้ชัดก่อน ไม่งั้นจะแก้ยากภายหลัง

| # | ประเด็น | ทางเลือก | ค่าตั้งต้นในร่างนี้ |
|---|---------|---------|-------------------|
| 1 | ขอบเขต "ไม่เคยกระทำผิด" ของกระดานเกียรติยศ | ตั้งแต่แรกเข้า / เฉพาะปีนี้ / ไม่นับความผิดเบาที่เกิน 1 ปี | ตั้งแต่แรกเข้า |
| 2 | คะแนนยกยอดข้ามปีหรือไม่ | ยกยอด / คืน 100 ทุกปี | ยกยอด |
| 3 | นักเรียน ม.3 ขึ้น ม.4 ที่โรงเรียนเดิม | เริ่มนับใหม่ / ยกยอดคะแนนความดี | เริ่มนับใหม่ |
| 4 | ให้กู้คืนคะแนนได้หรือไม่ | ได้ไม่เกิน 50% / ไม่ให้ | ได้ไม่เกิน 50% |
| 5 | คะแนนความประพฤติผูกกับผลการเรียนหรือไม่ | ไม่ผูก / ใช้ประกอบการประเมินคุณลักษณะ | ใช้ประกอบเท่านั้น |
| 6 | ครูผู้สอนทุกคนบันทึกได้ หรือเฉพาะครูเวร | ทุกคน (รออนุมัติ) / เฉพาะครูเวร | ทุกคน รออนุมัติ |
| 7 | เผยแพร่ชื่อเต็มบนหน้าเว็บ | ชื่อเต็ม (ต้องมีความยินยอม) / ปกปิดนามสกุลทุกคน | ตามความยินยอมรายคน |

> **ข้อ 1 กับ 5 ควรผ่านความเห็นชอบของคณะกรรมการสถานศึกษา** เพราะกระทบสิทธิของนักเรียนโดยตรง

## 8.2 แผนพัฒนา 4 เฟส

### เฟส 1 — ระบบหลัก (2–3 เดือน) 🎯 *ต้องมีก่อนเปิดใช้*

| งาน | รายละเอียด |
|-----|-----------|
| ฐานข้อมูล | ตามไฟล์ `db/schema.sql` ในรีโปนี้ |
| ข้อมูลพื้นฐาน | นำเข้านักเรียนจาก DMC/SGS, จัดห้อง, กำหนดครูที่ปรึกษา |
| หลักเกณฑ์ | นำเข้าเกณฑ์ที่คณะกรรมการอนุมัติ (ปรับจาก `db/seed_rules.sql`) |
| บันทึกพฤติกรรม | หน้าจอบันทึกที่เร็วที่สุดเท่าที่ทำได้ + หน้าอนุมัติ |
| หน้าหลัก | กระดานเกียรติยศ 2 ระดับ อ่านจากสแนปช็อต |
| รายงาน | R01, R02, R03, R05 |
| สิทธิ์ | RBAC ตามเมทริกซ์ใน `docs/05` |

**เกณฑ์วัดความสำเร็จของเฟส 1**: ครูอย่างน้อย 70% บันทึกอย่างน้อย 1 ครั้งใน 1 เดือน

### เฟส 2 — ความเป็นธรรมและการสื่อสาร (2 เดือน)

- แจ้งเตือนผู้ปกครองผ่าน LINE Messaging API (พร้อมเทมเพลตข้อความที่โรงเรียนแก้ไขเอง)
- ระบบอุทธรณ์เต็มรูปแบบ
- แผนปรับเปลี่ยนพฤติกรรมและการกู้คืนคะแนน
- คำสั่งลงโทษพร้อมออกเอกสารและติดตามการรับทราบของผู้ปกครอง
- รายงาน R04, R06, R07, R08

### เฟส 3 — ใช้งานสะดวกและเห็นภาพ (2 เดือน)

- PWA สำหรับครู + สแกน QR บนบัตรนักเรียน (เป้าหมาย: บันทึก 1 รายการภายใน 20 วินาที)
- แดชบอร์ดผู้บริหารพร้อมกราฟแนวโน้ม
- พอร์ทัลนักเรียน/ผู้ปกครองดูคะแนนตนเอง
- รายงาน R09, R10, R11, R12
- ออกเกียรติบัตรอัตโนมัติสำหรับผู้ติดกระดานเกียรติยศ

### เฟส 4 — เชื่อมโยงและต่อยอด (ต่อเนื่อง)

- เชื่อมข้อมูลกับ SGS / DMC (นำเข้ารายชื่ออัตโนมัติ ลดงานซ้ำซ้อน)
- เชื่อมกับระบบดูแลช่วยเหลือนักเรียน (SDQ, EQ, การเยี่ยมบ้าน)
- ส่งออกผลการประเมินคุณลักษณะอันพึงประสงค์เข้า ปพ.
- รายงาน R13, R14 (SAR)
- ระบบเตือนล่วงหน้า (ดูข้อ 8.4)

## 8.3 ข้อเสนอแนะเชิงออกแบบที่สำคัญที่สุด 7 ข้อ

### 1. ทำให้ "ให้คะแนนความดี" ง่ายกว่า "หักคะแนน"
ระบบคะแนนความประพฤติในโรงเรียนส่วนใหญ่ล้มเหลวเพราะกลายเป็น "ระบบจับผิด"
ภายใน 1 ภาคเรียน ข้อมูลจะมีแต่ความผิด นักเรียนเกลียดระบบ ครูรู้สึกเป็นตำรวจ
มาตรการที่แนะนำ
- หน้าจอบันทึกให้ปุ่ม "ความดี" อยู่ก่อนและใหญ่กว่า
- ตั้งเป้าหมายรายเดือนให้ครูที่ปรึกษาบันทึกความดีอย่างน้อย 5 รายการ/ห้อง
- ตรวจสอบอัตราส่วนความดี:ความผิด ในรายงาน R09 ถ้าต่ำกว่า 3:1 ถือว่าระบบเริ่มเบี่ยงเบน

### 2. ความเร็วของหน้าจอบันทึกสำคัญกว่าฟีเจอร์อื่นทั้งหมด
ถ้าครูต้องกด 7 ครั้งเพื่อบันทึก 1 รายการ ระบบจะตายภายใน 1 ภาคเรียนไม่ว่าจะสวยแค่ไหน
เป้าหมายคือ **สแกน QR → เลือกเกณฑ์ → ส่ง = 3 การกระทำ ภายใน 20 วินาที**

### 3. ทุกความผิดต้องมี "สิ่งที่ทำต่อ" ไม่ใช่แค่ตัวเลขที่ลดลง
การหักคะแนนอย่างเดียวไม่เปลี่ยนพฤติกรรม ระบบต้องบังคับให้ทุกความผิด severity ≥ 2
ผูกกับกิจกรรมแก้ไขหรือการพูดคุยเสมอ (`improvement_plans`)

### 4. เก็บ "บริบท" ไม่ใช่แค่ "ข้อเท็จจริง"
คอลัมน์ `detail`, `location`, `occurred_at` ที่บันทึกครบทำให้ตอบคำถามเชิงระบบได้
เช่น นักเรียนมาสายเพราะรถรับส่ง ไม่ใช่เพราะขาดวินัย — แก้ที่ตารางรถ ไม่ใช่หักคะแนนเด็ก

### 5. อย่าให้คะแนนกลายเป็นเป้าหมายในตัวมันเอง
เมื่อคะแนนกลายเป็นตัวชี้วัด นักเรียนจะเรียนรู้ที่จะ "เก็บแต้ม" แทนที่จะเป็นคนดี
มาตรการ: ให้น้ำหนักคุณภาพของเรื่องราวมากกว่าจำนวนครั้ง, ยกย่องความดีที่ไม่มีในเกณฑ์ด้วย
(เปิดช่อง "ความดีอื่น ๆ" ให้ครูเสนอ แล้วคณะกรรมการพิจารณาให้คะแนน)

### 6. เตรียมข้อมูลให้ตอบคำถามได้ตั้งแต่วันแรก
โครงสร้าง ledger + snapshot ทำให้ตอบคำถามยาก ๆ ได้โดยไม่ต้องแก้ระบบภายหลัง เช่น
"ทำไมลูกผมคะแนน 92 ไม่ใช่ 94" หรือ "เดือนที่แล้วลูกอยู่อันดับ 8 ทำไมตอนนี้หลุด"

### 7. วางแผนสำหรับ "ปีที่สอง" ตั้งแต่ปีแรก
เรื่องที่มักลืมและทำให้ระบบพังในปีที่ 2
- การเลื่อนชั้นและจัดห้องใหม่ (โครงสร้าง `enrollments` รองรับแล้ว)
- การเปลี่ยนหลักเกณฑ์คะแนน (ระบบเวอร์ชันใน `behavior_rules` รองรับแล้ว)
- นักเรียนย้ายเข้า/ย้ายออกกลางปี (`admission_type`, `status` รองรับแล้ว)
- ครูที่ปรึกษาเปลี่ยน (`classroom_advisors` แยกตามปีแล้ว)

## 8.4 แนวคิดต่อยอดระยะยาว

| แนวคิด | คุณค่า | ความยาก |
|--------|-------|---------|
| **ระบบเตือนล่วงหน้า** ใช้รูปแบบข้อมูล (ขาดเรียนถี่ขึ้น + คะแนนลดเร็ว) ทำนายนักเรียนเสี่ยงหลุดจากระบบ | สูงมาก — ป้องกันเด็กออกกลางคัน | ปานกลาง |
| **กระดานความดีระดับห้อง/ระดับชั้น** | สร้างแรงจูงใจแบบทีม ครอบคลุมนักเรียนมากกว่า Top 10 | ต่ำ |
| **ธนาคารความดี** สะสมแต้มแลกสิทธิพิเศษ (เข้าห้องสมุดพิเศษ ที่จอดจักรยาน เกียรติบัตร) | เพิ่มแรงจูงใจต่อเนื่อง | ต่ำ |
| **เชื่อมกับการเยี่ยมบ้าน/คัดกรอง SDQ** | เห็นภาพนักเรียนรอบด้าน ไม่ตัดสินจากพฤติกรรมในโรงเรียนอย่างเดียว | ปานกลาง |
| **เปิด API ให้ระบบอื่นในโรงเรียนใช้** | ลดการกรอกข้อมูลซ้ำ | ปานกลาง |
| **รายงานเปรียบเทียบกับโรงเรียนในสังกัดเดียวกัน** (ข้อมูลรวม ไม่ระบุตัวตน) | เห็นตำแหน่งของโรงเรียนในภาพรวม สพม. | สูง |

## 8.5 ความเสี่ยงของโครงการและการรับมือ

| ความเสี่ยง | โอกาส | ผลกระทบ | การรับมือ |
|-----------|-------|---------|-----------|
| ครูไม่ใช้งาน ข้อมูลไม่ครบ | สูง | สูงมาก | ลงทุนกับความเร็วหน้าจอบันทึก + อบรม + ผู้บริหารใช้จริงให้เห็น |
| ระบบกลายเป็นเครื่องมือจับผิด | สูง | สูง | ติดตามอัตราส่วนความดี:ความผิด ตั้งเป้าอย่างน้อย 3:1 |
| ผู้ปกครองร้องเรียนเรื่องความไม่เป็นธรรม | ปานกลาง | สูง | มีขั้นอนุมัติ + ช่องอุทธรณ์ + audit log ครบตั้งแต่วันแรก |
| ข้อมูลรั่วไหล | ต่ำ | สูงมาก | มาตรการใน `docs/07` + ทดสอบกู้คืนข้อมูลปีละครั้ง |
| คะแนนไม่ตรงกับความจริง | ปานกลาง | ปานกลาง | ledger แบบ append-only ตรวจสอบยอดย้อนหลังได้เสมอ |
| ผู้พัฒนาเดิมไม่อยู่แล้ว ระบบดูแลต่อไม่ได้ | ปานกลาง | สูง | ใช้เทคโนโลยีมาตรฐาน + เอกสารครบ + โค้ดอยู่ในรีโปที่โรงเรียนเป็นเจ้าของ |

## 8.6 สิ่งที่ควรทำต่อจากรีโปนี้

1. นำโครงสร้างและหลักเกณฑ์ในร่างนี้เข้าที่ประชุมฝ่ายกิจการนักเรียน ปรับคะแนนให้ตรงกับระเบียบจริงของโรงเรียน
2. ตัดสินใจ 7 ประเด็นในข้อ 8.1 แล้วบันทึกไว้เป็นระเบียบโรงเรียน
3. เสนอคณะกรรมการสถานศึกษาให้ความเห็นชอบ
4. ทดลองใช้กับ **1 ระดับชั้น 1 ภาคเรียน** ก่อนขยายทั้งโรงเรียน — จะได้เห็นปัญหาจริงในขนาดที่แก้ไหว
5. ประเมินผลเมื่อจบภาคเรียนทดลอง แล้วปรับก่อนขยาย
